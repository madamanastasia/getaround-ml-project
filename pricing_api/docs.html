🚗 Getaround — Documentation de l’API Pricing

Documentation minimale requise, accessible via /docs : description de chaque endpoint (méthode, entrée, sortie, exemples).

Vue d’ensemble

Cette API expose un modèle de Machine Learning qui prédit rental_price_per_day en fonction des caractéristiques du véhicule.

  • GET / — Page d’accueil (HTML)
  • GET /health — Healthcheck (JSON)
  • POST /predict — Prédiction (JSON)
  • GET /docs — Documentation (HTML)

GET /HTML

  • Méthode GET
  • Entrée Aucune
  • Sortie Page HTML listant les endpoints disponibles

Exemple :

curl -s http://127.0.0.1:8000/

GET /healthJSON

  • Méthode GET
  • Entrée Aucune
  • Sortie JSON indiquant l’état du service

Exemple :

curl -s http://127.0.0.1:8000/health

Réponse attendue :

{
  "status": "ok"
}

GET /docsHTML

  • Méthode GET
  • Entrée Aucune
  • Sortie Page HTML contenant la documentation de l’API

Exemple :

curl -s http://127.0.0.1:8000/docs

POST /predictJSON

Retourne les prédictions de prix journalier (rental_price_per_day) pour une ou plusieurs lignes en entrée.

  • Méthode POST
  • Entrée JSON avec une clé input
  • Sortie JSON {"prediction": [...]} (une prédiction par ligne)
Formats acceptés :
  • Format matrice (requis pour l’évaluation) : {"input": [[...], [...]]}
  • Format dictionnaires (optionnel / compatibilité) : {"input": [{"feature": value, ...}]}

1) Format matrice (requis)

Chaque ligne doit contenir exactement 13 valeurs, dans l’ordre strict suivant (défini par feature_order.json) : 

model_key, mileage, engine_power, fuel, paint_color, car_type,
private_parking_available, has_gps, has_air_conditioning, automatic_car,
has_getaround_connect, has_speed_regulator, winter_tires
Types attendus :
  • model_key, fuel, paint_color, car_type → chaînes de caractères
  • mileage, engine_power → valeurs numériques
  • Les variables booléennes → true/false ou 0/1
Si une ligne n’a pas 13 valeurs, l’API renvoie une erreur 422.

Exemple de requête (matrice) :

{
  "input": [
    ["Citroën", 140411, 100, "diesel", "black", "convertible", 1, 1, 0, 0, 1, 1, 1]
  ]
}

curl

curl -X POST "http://127.0.0.1:8000/predict" \
-H "Content-Type: application/json" \
-d '{"input":[["Citroën",140411,100,"diesel","black","convertible",1,1,0,0,1,1,1]]}'

Python

import requests

payload = {
  "input": [
    ["Citroën", 140411, 100, "diesel", "black", "convertible", 1, 1, 0, 0, 1, 1, 1]
  ]
}

r = requests.post("http://127.0.0.1:8000/predict", json=payload)
print(r.json())

2) Format dictionnaires (compatibilité)

Ce format est accepté pour des raisons de compatibilité. Toutes les colonnes attendues doivent être présentes ; l’API réordonne ensuite selon FEATURE_ORDER.

Exemple de requête (dictionnaires) :

{
  "input": [
    {
      "model_key": "Citroën",
      "mileage": 140411,
      "engine_power": 100,
      "fuel": "diesel",
      "paint_color": "black",
      "car_type": "convertible",
      "private_parking_available": true,
      "has_gps": true,
      "has_air_conditioning": false,
      "automatic_car": false,
      "has_getaround_connect": true,
      "has_speed_regulator": true,
      "winter_tires": true
    }
  ]
}

Réponse

Une prédiction par ligne.

{
  "prediction": [97.15]
}

Erreurs possibles

  • 422 — entrée invalide (mauvaise dimension de matrice, colonnes manquantes en mode dictionnaire, JSON invalide)
  • 500 — erreur interne lors de la prédiction (échec du modèle)

Notes

  • L’API supporte des prédictions en batch (plusieurs lignes dans input).
  • Les catégories inconnues peuvent être gérées par le pipeline du modèle (selon l’entraînement).
  • Pour éviter les erreurs 422, respecter strictement l’ordre et le nombre de features en mode matrice.
